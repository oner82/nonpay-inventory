# 분리 저장 전환 기록 — 2026-11-08

## 현재 상태

- 사용자가 처방코드, 재고 제품, 코드 연결, 케이스, 입출고의 분리 관리를 승인했다.
- 로컬 구현 및 아래 검증을 완료했다. 운영 배포·보안 규칙 게시·운영 전환·코드 등록은 아직 실행하지 않았다.
- 전환 후 구버전 화면은 저장이 거부되므로 미저장 입력 정리를 요청했고, 사용자가 정리 완료 및 즉시 배포·전환을 승인했다. 승인 범위의 운영 전환을 진행한다.
- 기존 CLAUDE.md의 작업 전 변경분 및 다른 미추적 파일은 보존했다. 배포할 때 전체 디렉터리를 추가하지 않는다.

## 저장 방식

- `app/main`: `storageVersion:2`, 현재 generation, revision, 갱신시각, 변경 경로 목록만 저장.
- `inventoryData/{generation}/{group}/{id}`: 제품, 케이스, 입고, 설정 등의 각 항목을 독립 문서로 저장. 기존 ID와 업무 필드는 유지한다.
- `prescriptionCodes`: 코드·명칭. `prescriptionLinks`: 해당 코드의 기존 재고 연결·정책·감사 정보. 미확정 코드는 제품 연결 문서를 만들지 않는다.
- `changes/{revision}`: 변경 경로·시각·작성자. 마지막 50회 이내의 변경은 전체 목록 대신 해당 문서만 읽어 따라간다.
- 기존 임플란트·업체·대기 장부 컬렉션은 그대로 둔다. 해당 장부를 이번 전환에서 삭제하거나 다시 생성하지 않는다.
- 기존 화면에는 합쳐진 state를 제공한다. 저장할 때 달라진 문서만 계산해 케이스·제품 재고·변경 이력·개정번호를 한 Firestore 거래로 저장한다.
- 과거 방 보충 기록, 업체관리 인체조직 예외, 포장 환산 및 현재 재고 계산식은 유지한다.

## 전환 및 복구 보호

1. 관리자 화면에서 다른 기기의 입력 중지를 확인한다.
2. 최신 기존 자료를 읽고 핵심 자료 JSON을 내려받는다. 서버 `inventoryArchives/{generation}`에도 전환 직전 원본을 저장한다.
3. 별도 generation에 150문서씩 복사한다. 활성 운영 문서는 아직 바꾸지 않는다.
4. 전체 문서·순서·값을 원본과 재조합해 대조한다. 복사 실패는 기존 운영 상태를 바꾸지 않으며 같은 전환 ID로 재개할 수 있다.
5. 기존 원본이 그대로인지 다시 확인한 한 거래에서만 새 generation을 활성화한다. 전환 중 다른 저장이 있으면 활성화를 거부한다.
6. 전환 후 구버전 전체 문서 쓰기, 개정번호 없는 개별 문서 쓰기, 원본 보관본 삭제를 서버 규칙으로 거부한다.

기존의 전체 문서 복원 버튼은 분리 저장에서 차단한다. 그 버튼으로 v2 포인터를 구형 자료로 덮어쓰면 안 된다. 새 관리자 화면의 핵심 자료 다운로드는 계속 사용할 수 있다. 별도 임플란트·대기 장부와 사진은 이 다운로드에 포함되지 않는다고 화면에 명시했다. 전환 후 복구는 입력을 중지하고 보관 원본과 이후 기록을 대조하는 관리자 절차로 처리해야 한다. 구형 Hosting 버전만 되돌리는 방식은 v2 자료를 읽지 못하므로 사용하지 않는다.

## 처방코드 등록 범위

- 11월 8일 인증된 앱의 설정 내보내기로 기존 118코드를 대조했다.
- 제공 자료 2,650코드에서 새 코드 2,559개, 기존 코드의 추가 명칭 1개를 준비했다. 전체 합집합은 2,677코드다.
- 추가 명칭은 기존 미연결 코드의 영문 명칭이며, 기존 국문 명칭을 지우지 않는다.
- `tmp/mapping-notes-20261108/catalog-insert-prepared.json`은 코드·명칭만 포함하는 로컬 등록 자료다. Git/Hosting에 포함하지 않는다.
- 파일 전체의 형식과 기존 연결 코드의 새 명칭 충돌을 먼저 검사하고 100코드씩 등록한다. 중단 후 같은 파일로 재개해도 이미 있는 코드·명칭은 중복되지 않는다.
- 물류 후보 연결, 수량 환산, 제품 추가, 케이스 생성, 재고 차감은 이 등록에서 하지 않는다. 운영 전환 때 최신 자료로 다시 대조한다.

## 운영 반영 전 확인

- 변경 앱 파일, 새 저장 모듈 2개, 버전 2.22.0 및 `security/firestore-v2.rules`만 검토한다. tmp/outputs/사용자 자료는 배포에 포함하지 않는다.
- Hosting은 main push로 자동 배포된다. 보안 규칙은 기존 워크플로의 Hosting 배포에 포함되지 않으므로 별도 게시 및 게시본 대조가 필요하다.
- 새 규칙은 기존과 같은 승인된 관리자만 허용한다. 직원 권한·신규 관리자 계정·공개 접근을 추가하지 않는다.
- 새 Hosting이 실제로 로드되고, 인증된 관리자가 구형 자료를 읽는지 확인한 후 전환한다.
- 운영 전환 후 제품별 재고, 기존 케이스·입고·원장·수술 수, 작성자·수정 이력, 코드 목록을 전환 직전 자료와 비교한다. 코드 등록 후에도 재고·케이스·입고가 같아야 한다.
- 초기 접속에는 해당 generation의 자료를 읽는다. 장기 기록의 기간별 조회·보관 기능은 이번 범위에 포함하지 않았다.
