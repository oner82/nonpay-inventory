# 저장된 케이스의 확인된 재고 연결 소급 반영

## 요청과 범위
사용자가 기존 케이스에도 이번 연결을 적용하고 이미 차감된 수량은 중복 차감하지 않도록 요청했다.
이번 확인 자료에서는 10케이스의 처방 연결 수량과 productIds 차감 내역이 모두 일치한다.
추가 대상은 OSTEOSPARX 2케이스 각 1개, Pulsavac-tip 1케이스 1세트다.
IRRIGATOR 4케이스는 실제 Linvatec/Stryker 사용 제품 질문 중이며 추정하지 않는다.

## 구현과 보존
- 관리자 설정에서 미리보기 후 적용. 현재 직접/장부 연결 정책과 정확한 처방명을 모두 확인한다.
- 미연결 행만 추가하며 이미 연결·차감한 행은 그대로 보존. 코드가 같아도 실제 제품 선택이 필요한 항목은 보류한다.
- 케이스의 연결행 합계와 기존 productIds가 일치하지 않으면 케이스 전체 보류.
- 처방 원본·기존 수량·기존 감사기록 보존. 소급 반영 전후 연결행 감사기록을 추가한다.
- 기존 재고 계산식을 사용한다. 기존 단위·기초재고·입고는 변경하지 않는다.
- 미리보기 이후 데이터가 바뀌면 다시 점검하도록 중단한다. 재실행 시 반영 완료된 행은 추가하지 않는다.
- 케이스·재고·필요한 업체 장부를 한 거래에 저장. 기존 수기/마감 장부는 추정 덮어쓰기하지 않고 기존 장부 보호 검사를 사용한다.
- 반영 전후 핵심 자료와 업체 장부 JSON을 로컬 다운로드로 백업. 재조회 후 장부 제품별 수량도 대조한다.
- 보안 규칙·권한·배포 설정은 변경하지 않는다.

## 검증
- 실제 자료 기반 신규 회귀: 3행만 추가, 기존 차감 보존, 재실행 무변경, 동시 변경 거부, 부족 재고 거부, 기록 불일치 보류, 제품 선택, 새 명칭 거부, 업체관리품 재고 제외.
- 실제 앱+Firestore 에뮬레이터: 미리보기·선택/보류 전환, 두 번째 장부 실패 시 전체 취소, 3케이스 적용/장부 2건, 새로고침 후 재반영 비활성화, 다른 기기 변경 감지, 모바일 폭, 모든 모듈 로드 통과.
